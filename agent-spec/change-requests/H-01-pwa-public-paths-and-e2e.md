# CR H-01 · Public PWA paths in middleware, ignore the generated worker, offline e2e spec

**Status:** approved by project owner 2026-11-03. Applied to `tasks/H-01.md` (also touches `middleware.test.ts`). Items 1 and 2 (public PWA paths, ignore the generated worker) are implemented in the same PR; `tests/e2e/offline.spec.ts` is an H-01 follow-up.

## Problem

1. **The middleware gates the manifest and the service worker.** `middleware.ts` (AUTH-04) treats every path not in `PUBLIC_PREFIXES` as protected, so `/manifest.webmanifest` and `/sw.js` get a `307` to `/login` when the request has no session.
   - Browsers fetch the manifest **without credentials**, so the redirect always happens. Next.js adds `crossorigin="use-credentials"` only on Vercel previews (`VERCEL_ENV=preview`), so in production the app can't be installed (REQ-NF-01).
   - A service worker script can't come from a redirect. Registration fails on `/login` and the other signed-out pages, and sign-in is a client-side navigation, so the worker only registers on the user's next full page load while signed in. Until then, nothing is available offline (REQ-NF-02).

   Neither file holds private data. The manifest is static and the worker is a build artifact.
2. **The worker is a build artifact in `public/`.** `@serwist/next` writes `public/sw.js` on every `next build`. `.gitignore` and `eslint.config.mjs` (F-01) don't ignore it. After a local `pnpm build`, the file shows up as untracked, and `pnpm lint` fails on the minified code (8 errors, 74 warnings). CI isn't affected because it lints before it builds. Prettier already skips the file because it's gitignored once (2) lands.
3. **No test paths.** H-01 owns `app/sw.ts` but not `app/sw.test.ts` next to it, which AGENTS.md §5 requires. The PR ships it on the same basis as the precedent `features/songs/ui/form/toInput.test.ts`. The acceptance criterion is a Playwright offline check, and `tests/e2e/` isn't owned (same situation as the LIB-17 and LIST-07 CRs).

## Proposed diff

`middleware.ts` (AUTH-04):

```diff
 const PUBLIC_PREFIXES = [
   '/login',
   …
   '/dev',
+  // PWA (H-01): the manifest is fetched without cookies, and a worker script can't be a redirect.
+  '/sw.js',
+  '/manifest.webmanifest',
   // Framework internals the matcher doesn't already skip (dev HMR, etc.).
   '/_next',
 ] as const;
```

Plus a case in `middleware.test.ts`: both paths are public; `/sw.jsx` and `/manifest.webmanifest.bak` aren't, because a prefix only matches itself and the paths below it.

`.gitignore` and `eslint.config.mjs` `ignores` (F-01):

```diff
+# PWA worker, generated by `next build` (H-01)
+public/sw.js
+public/sw.js.map
+public/swe-worker-*.js
```

```diff
       '.claude/**',
+      'public/sw.js',
+      'public/swe-worker-*.js',
     ],
```

`agent-spec/tasks/H-01.md` frontmatter (then regenerate `INDEX.md` / `tasks.json`):

```diff
-owns: ["app/manifest.ts", "app/sw.ts", "public/icons/"]
-touches: ["next.config.ts"]
+owns: ["app/manifest.ts", "app/sw.ts", "app/sw.test.ts", "public/icons/", "tests/e2e/offline.spec.ts"]
+touches: ["next.config.ts", "middleware.ts", ".gitignore", "eslint.config.mjs"]
```

## What H-01 ships meanwhile

- The worker, manifest, icons and offline banner all work for signed-in users. The worker registers on the first full page load of a signed-in session, and installing works on Vercel previews.
- The H-01 author checked the acceptance scenario by hand with Playwright against `next build && next start` on the local stack, with the middleware change above applied locally and not committed. Steps: sign in, open a setlist, open its chord chart, `context.setOffline(true)`, reload. The setlist rendered with the offline banner, and the chord chart opened from cache. An unsaved page showed the offline page with a link to the saved setlist. Without the middleware change, the same run passes after one full reload once signed in.
- A follow-up adds `tests/e2e/offline.spec.ts` with that scenario. The service worker only exists in production builds, so the spec runs against Vercel previews (as `e2e.yml` already does) or `next start`. It skips itself unless test accounts are supplied (`E2E_MEMBER_EMAIL` / `E2E_MEMBER_PASSWORD`, as in `song-form.spec.ts`). It also needs a seeded setlist whose song has a stored PDF, and the seed doesn't upload Storage objects today.

## Affects

- **AUTH-04** (`middleware.ts`): two more public prefixes. No behaviour change for any other route.
- **F-01** (`.gitignore`, `eslint.config.mjs`): three ignore lines.
- **H-01**: two extra owned paths, three extra touches. No other task owns them.
