# DB-03 · RLS policies


**Goal.** Database-level enforcement of the permission matrix.

## Read first
- `agent-spec/AGENTS.md`
- `agent-spec/SPEC.md`
- `agent-spec/contracts/permissions.md`
- `agent-spec/contracts/schema.md`
- Output of `DB-01` (merged on main)

## Requirements
- `REQ-AUTH-07` — Roles: `member`, `contributor`, `music_leader`, `admin`. Permissions per `contracts/permissions.md`, enforced in Postgres RLS **and** server code.
- `REQ-LIST-08` — Setlists are readable by all members (supports "what other branches are using"); playlists are private to their owner unless shared.
- `REQ-NF-05` — Every server mutation is authorized server-side; RLS is defense in depth.

## Deliverables
- [x] Helper functions from the contract
- [x] RLS enabled on every table; policies per action row
- [x] Storage policies on bucket `resources` (read: any active user; write: contributor+)

## Acceptance criteria
- [x] No table has RLS disabled (query `pg_tables` in a test)
- [x] Disabled user gets zero rows from every table
- [x] Definition of Done in `AGENTS.md` §5 is satisfied

## Boundaries
- **Owns** (create/modify freely): `db/migrations/0003_rls.sql`
- Anything else: do not edit. Open a change request (`AGENTS.md` §6).

## Notes

- `0003_rls.sql` was created with `pnpm db:generate --custom --name rls` (CR DB-01-migrate-scripts), which also adds the `db/migrations/meta/` journal entry and `0003_snapshot.json`.
- Integration tests live in `tests/db/0003_rls.int.test.ts` and assume migrations are applied (`pnpm db:migrate`), as in CI. They run each check as `authenticated`/`anon` with `request.jwt.claims` in a rolled-back transaction.
- Policies bind `authenticated` only; server code (`postgres`, `service_role`) bypasses RLS by design.
- Beyond the contract helpers, the migration adds a `songs_guard_added_by` trigger (non-admins can't change `songs.added_by_branch_id` on update, which RLS can't express), revokes TRUNCATE/TRIGGER/REFERENCES on public tables from `anon`/`authenticated`, and creates the private `resources` bucket if missing (no-op on hosted projects, where OPS-01 creates it).
- Deliberate tightenings vs `can()` are listed in the DB-03 PR body.
